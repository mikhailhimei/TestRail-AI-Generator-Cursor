# JSON-моки из MCP-чата

Нужны обновлённое приложение/расширение TestRail AI Generator с разделом «Моки» и перезапущенный MCP. Общий протокол один для Codex, Gemini CLI, GitHub Copilot и других MCP-клиентов.

Для новых кейсов используйте `add_test_cases` и поле `jsonMocks` каждого кейса: массив объектов `name` (имя `.json`) и `json` (JSON-документ строкой).

Для существующих кейсов:
1. Прочитайте `get_extension_state`, найдите реальный `caseId` и текущие `sessionId`/`revision`.
2. Прочитайте нужный промпт через `get_extension_prompt`.
3. Вызовите `upsert_case_mocks` с `sessionId`, `expectedRevision`, `caseId`, `mocks: [{name, json}]`.
4. Перечитайте состояние и проверьте `cases[].jsonMocks`: названия и содержимое файлов.

Инструмент добавляет новые имена или обновляет существующие, сохраняя ID файлов, другие моки и поля ТК. JSON в предусловиях не является мок-файлом. Для переноса уже написанных JSON-пэйлоадов из предусловий не создавайте кейсы заново: используйте их существующие ID. Удалять исходный текст без явного запроса пользователя не нужно.

До 10 файлов суммарно до 1 МБ на кейс; имена без слешей и кавычек; содержимое проходит JSON.parse. Не используйте реальные секреты и персональные данные.

MCP сохраняет черновики, но не публикует файлы в TestRail. Вложения отправляются вместе с ТК из UI; для них нужны API TestRail и учётные данные.
