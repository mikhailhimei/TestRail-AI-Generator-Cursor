JSON-моки теперь являются файлами в разделе «Моки», а не только текстом в предусловиях.

- Общий MCP-инструмент `upsert_case_mocks` добавляет/обновляет именованные JSON-файлы существующего кейса, сохраняя сам ТК и другие файлы.
- `add_test_cases` принимает `jsonMocks` при создании новых кейсов.
- Инструкции MCP явно требуют проверять `cases[].jsonMocks` после записи и не выдавать JSON в предусловиях за сохранённые файлы.
- Поддержаны Codex, Gemini CLI, GitHub Copilot и другие совместимые MCP-клиенты. Задача генерации JSON-моков проверена для всех трёх CLI с тестовыми процессами.
- Расширение Chrome 1.1.2: именованные файлы, JSON-редактор, генерация AI, несколько моков на кейс и загрузка вложений через TestRail API. Сохранён выбор Codex/Gemini/Copilot.

Обновление: распакуйте новый архив своего MCP-клиента, обновите расширение, перезапустите MCP и откройте новый чат. Сервер должен показывать 7 инструментов, включая `upsert_case_mocks`. Для существующих кейсов попросите перенести JSON-пэйлоады из предусловий в `jsonMocks`, не создавая ТК заново. MCP сохраняет только черновики; отправка вложений в TestRail выполняется отдельно из UI и требует API/учётных данных.

Для HTTP MCP в Linux-приложении обновите также ветку приложения и перезапустите пользовательскую службу. Обновление только этого архива не изменяет отдельный сервер на порту 6252.

Архивы проверены на целостность, состав, исполняемые Unix-скрипты и доступность новых инструментов; контрольные суммы — SHA256SUMS.txt. Реальные аккаунты AI и TestRail в проверках не использовались.
