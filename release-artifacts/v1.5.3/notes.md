Исправлено сохранение JSON-моков при генерации кейсов из поля «Требования».

- Парсеры ответов AI и импорта больше не отбрасывают jsonMocks. Именованные файлы получают локальные ID, проверяются JSON, имена и лимиты. AI не может подставить подтверждение загрузки в TestRail.
- Общая инструкция формата ответа описывает jsonMocks как массив name/json. По запросу моков AI должен вернуть файлы, а не JSON в предусловиях.
- После генерации отдельно показывается количество кейсов и файлов моков.
- В параметрах генерации сохранён выпадающий список «Не разрешать чтение исходников» / «Разрешить чтение исходников». По умолчанию доступ выключен.
- Расширение Chrome 1.1.5 поддерживает Codex, Gemini и Copilot; MCP содержит прежние 7 инструментов.

Проверки: web/master extension/extension со всеми MCP собираются. Тесты проходят цепочку ответ AI → кейсы с двумя файлами для Codex, OpenAI и Gemini, импорт, невалидный JSON, дубли имён, генерацию JSON в редакторе и повтор загрузки вложений. Ответы AI/TestRail в тестах подставлены; реальные аккаунты не использовались.

Linux-приложение: git pull --ff-only origin feat/docker-local-server, npm run build:web, systemctl --user restart testrail-ai-generator. Затем обновите страницу и повторите генерацию. Ранее отброшенные файлы восстановить из черновиков невозможно; их можно сгенерировать заново или добавить через MCP к существующим кейсам.
