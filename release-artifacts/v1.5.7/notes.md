Расширение Chrome 1.1.8 и MCP runtime 1.5.7.

- Убраны сообщение о неподтверждённом создании ТК, ручной ввод Case ID и блокировка повтора. В созданных кейсах отправка доступна и после успешной загрузки: кнопка «Отправить повторно».
- Если ID известен, повтор обновляет тот же кейс; если ответ с ID потерян, разрешено повторное создание без ручного подтверждения (на стороне TestRail возможен дубль). Неизменённые подтверждённые вложения по-прежнему пропускаются.
- Исправлена проверка путей Windows D:/..., D:\..., путей с пробелами в кавычках и UNC. Явное разрешение чтения требуется до запуска CLI. Windows-путь для Linux-сервера отклоняется понятной ошибкой.
- Codex запускается в проверенном каталоге проекта с явным --cd. Read-only сохранён; инструкция требует абсолютных путей и -LiteralPath в PowerShell. Это устраняет отличия рабочего каталога; обхода политик безопасности нет. Реальная ошибка blocked by policy на компьютере пользователя требует повторной проверки после обновления.
- Загрузка JSON-вложений из TestRail при открытии ТК на редактирование пока не реализована. Веб-транспорт не изменялся: браузер обращается к вашему Linux-сервису, который отправляет запросы в TestRail; внешнего прокси нет.

Проверки: web/extension builds, тесты JSON-моков с повтором после ошибки и legacy-флагом, standalone server и 9 тестов MCP/runtime/установщика. Windows-пути проверены парсером и подставленной файловой системой; реальный Codex на Windows в этой среде не запускался.

Для Linux: обновите feat/docker-local-server, выполните npm run build:web и systemctl --user restart testrail-ai-generator, затем обновите страницу. Для Windows: обновите расширение и MCP-пакет, перезапустите MCP и выберите разрешение чтения исходников для генерации по проекту.
